# Skill: Dynamic LLM Router (モデル動的選定スキル)

## 📌 目的
ユーザーのリクエストを解析し、「個人情報の保護」「コスト最小化」「処理精度・速度の最大化」を同時に満たす最適なLLMモデルを動的に選択する。

## 🛡️ クリティカルルール（最優先）
1. **個人情報（PII）の完全ローカル隔離**
   - 入力データに氏名、住所、電話番号、メールアドレス、パスワード、クレジットカード情報、企業秘密の固有値が含まれる場合、外部APIへは絶対にそのまま送信しない。
   - 原則、LocalLLM内で匿名化（マスク処理）を行う。マスク処理が文脈上不可能な場合は、外部APIへのルーティングを禁止し、100% `LocalLLM` で完結させる。

2. **コスト・スピード最適化**
   - 外部APIを利用する場合、原則として最もコストパフォーマンスの高い `Claude Sonnet 4.6` をデフォルトとする。
   - `Claude Opus 5.5` や `Grok 4.7 Fast` などの上位・特殊モデルは、明確な必要性（複雑な推論、リアルタイム性など）がある場合のみ選択する。

## 📊 モデル選定マトリクス（ルーティング基準）
ユーザーのリクエスト内容、またはタスクの性質に応じて、以下の4つのルートから必ず1つを選定せよ。

- `local` (Qwen 3.5 9B): 定型文生成、簡単な要約、挨拶、または個人情報が分離できない場合。
- `sonnet-4.6` (Claude Sonnet 4.6): 【デフォルト】一般的なビジネスロジック、データ整形、標準的なプログラミング。
- `opus-5.5` (Claude Opus 5.5): 非常に複雑なアルゴリズム、複数ファイルにまたがるコードベースの依存関係解析。
- `grok-4.7-fast` (Grok 4.7 Fast): 爆速応答が必要な場合、最新のネット・SNSトレンド、大量のログ解析。

## 🔄 処理ワークフロー
1. **Step 1 (Qwen 3.5 9B)**: 入力を解析し個人情報を `[USER_NAME_1]` 等に変数化。対応表をローカルに保存し、マトリクスから `route` を決定。
2. **Step 2 (外部API実行)**: `route` に応じてマスク済みテキストと実行プラン（`plan`）を対象のAPI（Claude/Grok）に送信。
3. **Step 3 (デマスク)**: 外部から戻ったテキスト内の変数を、ローカルに保持していた実データに置換してユーザーに返却。
